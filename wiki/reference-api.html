CheckQ REST API — AI-ready 参考

本文面向 Agent / MCP / 外部脚本。所有端点相对基址 http://<host>:<port>（默认 8888）。
鉴权二选一：Cookie Session（POST /api/login）或 X-API-Key（POST /api/system/apikey 生成）。
Content-Type: application/json。所有响应 JSON；错误统一 { error: string } + HTTP 状态码。

0. 开放 API（给外部 Agent / 集成）

项值
基址http://checkq.local:18888
接口索引GET /api（免登录，返回认证方式与端点清单）
机器可读描述GET /api/openapi.json（OpenAPI 3.1，Agent 可自动生成客户端）
认证① x-api-key: <key>（推荐）② 会话 Cookie qsid
Key 生成设置 → API Key（可命名、选作用域、设回收日期；明文只显示一次）
作用域read 查看 / run 运行任务 / write 改配置；权限不足返回 403
回收日期到期自动失效并从列表移除（过期请求返回 401「已过期并被回收」）
限流登录 5 次/10 分钟（IP）+ 8 次/15 分钟（账号）；API 调用无固定限流
IP 名单每把 Key 可设 IP 允许名单（CIDR）；另有全局 IP 黑名单（登录与 API Key 同时生效）；不名单外返回 403

最小示例：

# 1) 只读 + 可运行 的 Key（面板生成）
curl -H "x-api-key: cq_xxxx" http://checkq.local:18888/api/flows
# 2) 跑一次签到
curl -X POST -H "x-api-key: cq_xxxx" http://checkq.local:18888/api/flows/<id>/run
# 3) 读人话日志（连续多次运行）
curl -H "x-api-key: cq_xxxx" "http://checkq.local:18888/api/flows/<id>/logs?limit=200"

完整说明见 docs/AGENT-ACCESS.md。

1. 鉴权

POST /api/login

{ "password": "..." }

响应：{ ok: true } + Set-Cookie: qsid=...（7 天有效）。登录失败 5 次/10 分钟 → 429。

POST /api/logout

清除会话。

X-API-Key（推荐给 Agent/MCP）

X-API-Key: <key>

通过 POST /api/system/apikey（需已登录）生成；重新生成后旧 Key 立即失效。GET /api/system/settings 返回 { hasApiKey, apiKey: "abcd1234…" }（仅前 8 位）。

GET /api/health

{ "ok": true, "version": "0.3.17" }

无需鉴权。

2. 通用字段

  • Flow：{ id, name, note, cron, timezone, enabled, jitterMinutes, retry, vars, nodes, edges, notify, log, tplId, createdAt, updatedAt, lastRun, nextRunAt }
  • Node：{ id, type, name, x, y, config }
  • Retry（任务级失败重试）：{ enabled, maxAttempts, backoff: "exponential"|"linear"|"fixed", baseDelayMs, maxDelayMs, jitter }。一次运行最多尝试 maxAttempts 次，只有最后一次仍失败才判定任务失败；默认 { enabled:true, maxAttempts:3, backoff:"exponential", baseDelayMs:5000, maxDelayMs:300000, jitter:true }。调试运行（debugStopId）不重试。
  • Log config：{ level: "all"|"failure"|"summary", record: "all"|"log"|"log-final", include: {reqHeaders,reqBody,resBody,varsSnapshot}, resBodyLimit, keywords: [{name,regex,from,into,stepId,negate}] }
  • Run：{ id, flowId, trigger, startedAt, finishedAt, status, durationMs, summary, vars, logs, finalMessage, attempts, attempt, maxAttempts }。attempts[] 每项 { attempt, startedAt, durationMs, ok, message, nextDelayMs? }
  • StepLog：{ stepId, index, name, type, ok, message, ms, missing, asserts, keywords, detail }

任务 (Flows)

方法路径说明
GET/api/flows列表（摘要：id/name/note/cron/timezone/enabled/jitterMinutes/retry/varsCount/nodesCount/tplId/template/lastRun/nextRunAt）。template = { id, name } —— 来源模板；派生任务的流程图始终是模板当前版本
POST/api/flows创建（body = Flow 对象；空 nodes 允许，仅草稿；显式 enabled:true 且给了 cron 时按请求启用）
GET/api/flows/:id详情（含 nodes/edges/vars/log/notify/template；派生任务返回的是模板当前流程）
PUT/api/flows/:id更新（部分字段合并）。派生任务改了脚本内容 → 自动转为独立任务，返回体 detached = 模板名
DELETE/api/flows/:id删除
POST/api/flows/:id/run{ stream?: bool, debugStopId?, debug? } 运行；stream=true → SSE（start/log/done）。失败按 flow.retry 自动退避重试，跑满次数才最终失败；调度触发时若上一次运行/重试尚未结束则跳过这一拍
POST/api/flows/:id/clone克隆为「·副本 N」，enabled:false
POST/api/flows/:id/curl生成等价 curl 命令（变量代入）
POST/api/flows/batch`{ action: run\enable\disable\delete, ids: [] }`
POST/api/flows/:id/notify-test测试通知渠道

4. SSE 运行协议

POST /api/flows/:id/run with { "stream": true }：

event: start
data: {"flowId":"...","name":"..."}

event: log
data: { "index":1, "name":"...", "type":"http", "ok":true, "message":"...", "ms":120, ... }

event: done
data: { "id":"run-xxx", "status":"success", "durationMs":..., "summary":"...", "logs":[...], "vars":{...} }

7. 错误码

HTTP含义
400参数/校验失败（validateFlow、空流程等）
401未登录 / API Key 无效
404资源不存在
429登录防爆破（5 次/10 分钟）
500引擎异常（成环、节点类型未知等）

8. Agent 调用最小示例

# 1. 生成 API Key（先用密码登录一次）
curl -s -c cq.txt -X POST http://host:8888/api/login -H 'Content-Type: application/json' -d '{"password":"..."}'
curl -s -b cq.txt -X POST http://host:8888/api/system/apikey

# 2. 用 Key 跑任务
curl -s -H 'X-API-Key: <key>' http://host:8888/api/flows
curl -s -H 'X-API-Key: <key>' -X POST http://host:8888/api/flows/<id>/run
